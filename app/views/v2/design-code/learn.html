Learn about design codes

{{ pageName }}

A design code is a set of design rules for the development of a site or area. Each rule sets clear, specific, measurable and visual parameters for physical development.

These rules turn the broad design policies in your local plan into requirements that are visual and that you can measure. They show applicants what you will accept before they apply, so that you can make faster and more consistent decisions.

A design code should:

  • be measurable
  • use numbers and diagrams rather than detailed policy wording
  • be simple, concise and specific to the place or type of development it applies to
  • give developers certainty about what you will accept
  • raise the standard of baseline design quality
  • allow enough flexibility for variety, creativity and innovation

You need to base your design code on the 7 features of well-designed places:

  • liveability
  • climate
  • nature
  • movement
  • built form
  • public space
  • identity

National design issues that you can set rules for

Check the design issues that you can set rules for. These design issues are for common types of development. You should use or adapt the existing issues and rules before writing your own.

When you should use a design code

Use a design code when you need specific control over design. If you want to allow more flexibility and only want to encourage good practice, use guidance instead. You can use design codes and guidance together in your master plan.

You must be clear whether something is a design code or guidance.

Choose your design code type

There are 3 types of design codes:

  • authority-wide (type-based)
  • area-specific
  • site-specific

Choose based on where the design code will apply and how much you already know about the sites.

Authority-wide (type-based)

This design code applies to the same type of development, wherever it happens in your area. For example, new homes, small sites or a type of street. They apply to repeat design issues and usually link to a planning policy.

Area-specific

Area-specific design codes apply to growth or priority areas. For example, a town centre, regeneration corridor or urban extension. They coordinate development across several sites, owners or phases and are often linked to a master plan. Authority-wide codes still apply in these areas.

Site-specific

These apply to a single site that’s usually in one ownership and link to a master plan. For example, to support an outline planning application. They give more certainty and detailed rules than type-based codes, as the site constraints are known.

How to structure your design code

Every design code has the same 4 parts, so that all applicants and other authorities can understand them.

The 4 parts of a design code
Design code The whole set of rules, with one name, status and boundary. For example, Planham Centre Design Code 2026.
Coding plan A map and key showing the boundary of the code and where each area type and character area applies. It does not need to cover your whole authority area.
Area types and character areas The places that share a set of rules.
Design code rules The individual requirements. Each rule deals with one design issue and applies to one or more area types or types of development.

Area types

Area types group places with the same physical characteristics. For example, street patterns and house types. Use area types to set the same requirements across similar places.

Examples of an area type include:

  • town or city centre
  • local centre
  • urban neighbourhood
  • suburbs
  • industrial area
  • rural settlements

Character areas

A character area has its own distinct qualities, including its culture, built form, architecture and materials. Use character areas to manage small changes in established neighbourhoods. If you have a lot of character areas, combine them into broader area types.

Where the code applies

State the geographic coverage of your code clearly and link each rule to a location on a map.

What each rule contains

Every design requirement is structured in the same way, using a ‘design code rule’.

Creating design code rules

Each design code rule must include the same parts.

The parts of a design code rule
National design issue reference The national design issue reference. For example, ‘M4i’.
Design issue The name of the issue that the rule deals with. For example, ‘Design for active travel’.
Design code rule reference The reference for where people can find the rule within the overall design code document. For example, ‘3.4.9’.
Requirement What the development must do, including numbers and units.
Reason Explain why the rule exists. Every rule must have a reason, so you can judge proposals.
Coverage The area types, sites or types of development the rule applies to.
Other considerations Related rules and other standards, so the rule does not duplicate or contradict them. For example, building regulations or biodiversity net gain.
Illustration A diagram, plan, section or 3D drawing that shows what is acceptable.

Find out how to write good design code rules.

Design code rule references

When referencing your design code rule, you need to include a national design issue reference and a local rule number.

National design issue reference

The national design issue references standardise all design issue references, so that every authority uses the same reference for the same issue. All authorities must set their local rules from these issues.

A national design issue reference has 3 parts, including the:

  • feature
  • design principle within that feature
  • design issue within that principle (this must be in lower case Roman numerals)

For example, in M4ii:

  • M is the feature - movement
  • 4 is the design principle within that feature - active travel
  • ii is the design issue within that principle - junctions and crossings

You need to use this national design issue reference with your design code rule reference.

Check the features and design principles you can include.

Local rule number

This number shows where people can find the rule within the overall design code document. It has 3 parts, including:

  • chapter
  • section
  • paragraph

An example local rule number is ‘3.4.9’, in this number:

  • 3 is the chapter (for example, ‘coding plan and area type’)
  • 4 is the section (for example, Planham area type)
  • 9 is the ninth numbered paragraph in chapter 3, section 4

Create a design code rule reference for planning.data.gov.uk

Each design code rule needs a planning.data.gov.uk reference.

You should combine your design code abbreviation and local rule number. For example, the reference for ‘Planham Centre design code, rule number 3.3.9’ should be pcdc-3-3-9.

Publish your design code on planning.data.gov.uk

Find out how to publish your design code as data.

Use your design code in decisions

Give your design code appropriate weight in planning decisions as part of the development plan. For example, in your local plan or as a supplementary plan.

You should:

  • make your design codes easy to find
  • tell applicants which design code rules apply to their site during pre-application
  • ask applicants to show how they comply in their design and access statement
  • check each relevant rule and work with applicants to resolve any non-compliance
  • refuse applications that do not meet the design code
